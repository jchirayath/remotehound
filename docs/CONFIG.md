# Configuration reference

Generated by `remotehound config-doc` from `internal/core/config` (CORE-1). Infrastructure settings below need a restart; behaviour settings (enrolment TTL, recording, roles, log level…) are edited at runtime on the **Settings** screen. Sign-in providers: see [AUTH_PROVIDERS.md](AUTH_PROVIDERS.md).

| Variable | Default | Required | Description |
|---|---|---|---|
| `RH_ENV` | `production` |  | production | development. Development enables RH_AUTH_MODE=dev on loopback only. |
| `RH_HTTP_ADDR` | `:8080` |  | Listen address for the UI, API and Guacamole proxy (plain HTTP; put TLS in front). |
| `RH_METRICS_ADDR` | `127.0.0.1:9090` |  | Internal listener for /metrics (Prometheus) and, if enabled, pprof. Never publish it. |
| `RH_SSH_ADDR` | `:2222` |  | Listen address of the embedded SSH tunnel server devices connect to. |
| `RH_SSH_PUBLIC_PORT` | `2222` |  | Port devices dial (as published on the host). Initial value for the ssh_public_port setting. |
| `RH_TUNNEL_BIND` | `127.0.0.1` |  | Address tunnel listeners bind on (a device's raw RDP/SSH/VNC). Must be reachable by guacd and nothing else: the bundle uses remotehound's address on the internal guac network. |
| `RH_TUNNEL_BIND_ALLOW_ANY` | `false` |  | Set true to allow binding tunnel listeners on 0.0.0.0/:: (exposes every device's desktop to anything that reaches the host — only behind a firewall you control). |
| `RH_TUNNEL_ADVERTISE_HOST` | `remotehound` |  | Hostname guacd uses to reach tunnel listeners (the container name in the bundle). |
| `RH_TUNNEL_PORT_MIN` | `20000` |  | First port of the tunnel listener range. |
| `RH_TUNNEL_PORT_MAX` | `20999` |  | Last port of the tunnel listener range (inclusive). |
| `RH_DATA_DIR` | `/data` |  | State, audit log, SSH host key and backups. Back this volume up. |
| `RH_RECORDINGS_DIR` | `/recordings` |  | Where guacd writes session recordings (mounted read-only into remotehound). |
| `RH_GUAC_RECORDING_PATH` | `/recordings` |  | The same directory as guacd sees it (recording-path parameter). |
| `RH_BUNDLE_LOG` | `` |  | Optional JSONL file of container logs written by the vector profile; shown as source=bundle in Logs. |
| `RH_PUBLIC_URL` | `` | always | External https URL of RemoteHound, e.g. https://rh.example.com. Initial value for the public_url setting. |
| `RH_AUTH_MODE` | `oauth` |  | oauth (sign in with the providers in RH_AUTH_PROVIDERS) | proxy (trusted authenticating proxy) | dev (loopback development only). |
| `RH_AUTH_PROVIDERS` | `` | when RH_AUTH_MODE=oauth | Comma-separated sign-in providers, shown in this order: entra, google, apple, facebook, github, oidc. |
| `RH_PROXY_EMAIL_HEADER` | `X-Forwarded-Email` |  | proxy mode: header carrying the authenticated user's email. |
| `RH_PROXY_NAME_HEADER` | `X-Forwarded-User` |  | proxy mode: header carrying the display name / user. |
| `RH_PROXY_GROUPS_HEADER` | `X-Forwarded-Groups` |  | proxy mode: comma-separated groups (mapped through the roles_map setting). |
| `RH_PROXY_SUBJECT_HEADER` | `` |  | proxy mode, optional: header carrying the IdP's stable subject (e.g. X-Auth-Request-User from oauth2-proxy). When set, it is the identity key and the email header is for display and first-time matching only, so an email change or reuse at the IdP cannot move an account. Empty = identity keyed on the email header. On first sign-in after enabling it, a user's existing email-keyed proxy identity is converted to the subject. |
| `RH_TRUSTED_PROXIES` | `` |  | Comma-separated CIDRs allowed to set X-Forwarded-For and (proxy mode) identity headers, e.g. 172.18.0.0/16. |
| `RH_PROXY_SECRET` | `*(secret)*` | when RH_AUTH_MODE=proxy | proxy mode: value the proxy must send in X-RemoteHound-Proxy-Secret on every request (generate with: remotehound gen-secret). Required: a trusted CIDR alone would admit anything else on that network. |
| `RH_PROXY_LOGOUT_URL` | `` |  | proxy mode, optional: where Sign out sends the browser so the PROXY's session ends too, e.g. https://sso.example.com/oauth2/sign_out?rd=https%3A%2F%2Frh.example.com%2Fsigned-out. Without it Sign out only ends RemoteHound's session and the proxy signs you straight back in. |
| `RH_PROJECT_URL` | `https://github.com/jchirayath/remotehound` |  | Where Overview's "Learn more about RemoteHound" link goes: the project site, or your own page about this install. |
| `RH_IDP_LOGOUT_URL` | `` |  | Optional: identity provider sign-out page offered on the signed-out screen (e.g. https://login.microsoftonline.com/common/oauth2/v2.0/logout), for shared computers. |
| `RH_CONTROL_URL` | `` |  | Optional: internal URL of the rh-control helper (e.g. http://rh-control:9091). Enables start/stop/restart and container logs on the Services screen. Empty = status only. |
| `RH_CONTROL_TOKEN` | `*(secret)*` |  | Shared token between remotehound and rh-control (64 hex chars; remotehound gen-secret prints one). Or RH_CONTROL_TOKEN_FILE. |
| `RH_CONTROL_TOKEN_FILE` | `` |  | File holding RH_CONTROL_TOKEN. |
| `RH_CONTROL_LISTEN` | `:9091` |  | rh-control only: listen address. Put it on a network only remotehound can reach; never publish it. |
| `RH_CONTROL_DOCKER_SOCKET` | `/var/run/docker.sock` |  | rh-control only: path of the Docker Engine socket mounted into the helper. |
| `RH_BOOTSTRAP_ADMIN` | `` |  | Email that becomes admin on first sign-in while no admin exists. |
| `RH_SECRET_KEY` | `*(secret)*` |  | 64 hex chars (32 bytes): master key for session signing and credential sealing. Or RH_SECRET_KEY_FILE. |
| `RH_SECRET_KEY_FILE` | `` |  | File holding RH_SECRET_KEY. |
| `RH_GUAC_URL` | `http://guacamole:8080/guacamole` |  | Internal URL of the Guacamole web app. |
| `RH_GUAC_PUBLIC_PATH` | `/guacamole` |  | Path under RH_PUBLIC_URL where RemoteHound proxies Guacamole. Must equal the path of RH_GUAC_URL. |
| `RH_GUAC_JSON_SECRET` | `*(secret)*` |  | 32 hex chars: the JSON_SECRET_KEY given to the guacamole container. Or RH_GUAC_JSON_SECRET_FILE. |
| `RH_GUAC_JSON_SECRET_FILE` | `` |  | File holding RH_GUAC_JSON_SECRET. |
| `RH_GUACD_ADDR` | `guacd:4822` |  | guacd host:port, used by integration checks. |
| `RH_LOG_LEVEL` | `INFO` |  | Initial log level; change it at runtime on the Debug screen. |
| `RH_DEBUG_PPROF` | `false` |  | Expose net/http/pprof on RH_METRICS_ADDR. Off in production unless you are debugging. |
| `RH_VERSION` | `` |  | Overrides the reported service.version (set by the image build). |
| `RH_AUTH_ENTRA_CLIENT_ID` | `` |  | entra: client / application ID. |
| `RH_AUTH_ENTRA_CLIENT_SECRET` | `*(secret)*` |  | entra: client secret (or use _CLIENT_SECRET_FILE). |
| `RH_AUTH_ENTRA_CLIENT_SECRET_FILE` | `` |  | entra: file holding the client secret. |
| `RH_AUTH_ENTRA_SCOPES` | `` |  | entra: override the default scopes (space-separated). |
| `RH_AUTH_ENTRA_TENANT` | `` |  | entra: REQUIRED: your directory (tenant) ID; or organizations / common for multi-tenant (then ALLOWED_TENANTS is required). |
| `RH_AUTH_ENTRA_ALLOWED_TENANTS` | `` |  | entra: multi-tenant only: comma-separated tenant IDs whose users may sign in (any other tenant is refused). |
| `RH_AUTH_ENTRA_TRUST_EMAIL` | `` |  | entra: true if emails from this issuer are verified by you (single-tenant directory) even without email_verified. |
| `RH_AUTH_GOOGLE_CLIENT_ID` | `` |  | google: client / application ID. |

| `RH_AUTH_GOOGLE_CLIENT_SECRET_FILE` | `` |  | google: file holding the client secret. |
| `RH_AUTH_GOOGLE_SCOPES` | `` |  | google: override the default scopes (space-separated). |
| `RH_AUTH_APPLE_CLIENT_ID` | `` |  | apple: client / application ID. |

| `RH_AUTH_APPLE_TEAM_ID` | `` |  | apple: Apple developer team ID. |

| `RH_AUTH_FACEBOOK_CLIENT_ID` | `` |  | facebook: client / application ID. |
